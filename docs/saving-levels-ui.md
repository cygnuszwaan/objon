# Saving, levels, UI and collectibles

Checkpoint and save/restore (the saveable contract, `Game`, level loading, respawn), the finish, HUD and menus, touch controls, collectibles and points, the parallax backdrop. Read `objon.md` (the core: setup, layers and groups, contracts, invariants, docs index) first.

Covers: Gem; Points and bonus gem; Gem counter; Medkit; Parallax backdrop; Finish; Health bar; Level-complete overlay; Pause menu; Touch controls; Checkpoint and save/restore (Saveable contract; `Game` API; Level loading; Respawn flow; What each type saves; Not saved; Checkpoint; Live pitfalls)

- **Gem** (`gem.gd`): `Area2D` in group `"gem"`, calls `collect_gem()` on whatever it overlaps if that body has the method (mirrors the `take_hit` duck-typing convention rather than checking a group name), disables monitoring and frees itself immediately on pickup.
- **Points and bonus gem**: `Player.points` is the score; `add_points(amount) -> bool` (duck-typed like `collect_gem()`/`heal()`) is its only writer: it ignores a dead or dancing player and non-positive amounts, emits `points_changed(total, delta)` and spawns the `PointsPopup` feedback. The surf also awards through it (clean landings, bowled enemies, skim distance; see Scoring under Surf). `gem_1.gd` (`points` export, 5) calls `collect_gem()` then `add_points()`; `medkit.gd` (`points` 10) awards through `collect_medkit()` whether or not the heal was needed; `gem_2.gd` + `gem_2.tscn` (`sprites/collectibles/gem2.png`, 16×64 = 4 frames at 10 fps, `points` 50) is the bonus gem: it calls `add_points()` only, is in group `"bonus_gem"` and deliberately **not** `"gem"`, so it never enters `gems_total` or the finish's unlock percentage, and plays `collectibles/collectible` variant 1 (collectible2; the variant index wraps until the file exists). **Power** (roadmap 7.1, gem trails): `gem_2.tscn` carries a `PowerTarget` child and `gem_2.gd` implements `set_powered()` and `set_powered_initial()`, with `invert` exported on its root like the door's: powered = present and collectible, unpowered = hidden with `monitoring` off (switched deferred, since a timed button or speed trap can change state inside a physics callback), so one source can switch a whole trail on and off. An unwired gem is simply present. It keeps no power state: it saves nothing, a collected gem is absent from the snapshot, and an uncollected one re-derives from its restored sources through `set_powered_initial()`. A gem that reappears under the player is collected by polling its overlaps for `RECHECK_FRAMES` (3) physics frames, since a body already inside never enters it again, and `_taken` stops a second overlap in one frame from awarding twice. Wire each gem's `PowerTarget.sources` per instance (Editable Children), or attach a conductor wire by adjacency. `points` is per instance and the default 50 is a bonus-gem value; a trail value needs a `p<N>` popup animation, so use 5 or 10 unless new art exists. `gem_2.gd` is `@tool` only for a configuration warning (`get_points_warnings()`, read from the animations in `points_popup.tscn`) that flags a `points` value with no art; the points are still awarded without it. No new sound: the pickup sound is unchanged. `points` is part of the player's `save_state()`, so score banked before a checkpoint survives a restore (pickups taken before it stay gone) and `restart_level()` resets it. **Popup** (`scenes/effects/points_popup.gd` + `.tscn`, `AnimatedSprite2D`): the player spawns one in its parent at `global_position + points_popup_offset` (default `(0, -20)`, above the head), world space so it stays where it appeared; `points` selects the animation `p<points>` (`sprites/effects/{5,10,20,50}points.png`, 16×160 = 10 frames, 10 fps, each with its own upward drift drawn in), `rise_px` (16) adds a further tween drift over the same duration, and it frees itself on the last frame. A points value with no matching animation warns and shows nothing, so a new reward value needs a new `p<N>` animation. Physics interpolation is off on the popup (it moves in idle time). **Points display** (`scenes/ui/points_display.gd`, `class_name PointsDisplay`): `CanvasLayer` (layer 5) instanced as a child of `player.tscn`, built in code (placeholder default-font `Label` at the top-left, `POINTS  N`, popping on each gain); it syncs from the player deferred at load and follows `points_changed`.
- **Gem counter** (`scenes/ui/gem_display.gd`, `class_name GemDisplay`): `CanvasLayer` (layer 5) instanced as a child of `player.tscn` like `PointsDisplay`, built in code: a row under the points counter (`top` 56 px, `margin` 16) of the first frame of `sprites/collectibles/gem1.png` as a `TextureRect` (`icon_size` 32 px, a placeholder until UI art exists) and a default-font `Label`, `collected / total`. It follows `gem_collected` (the row pops) and syncs deferred at load; the level's total is only counted in the player's own deferred `_count_gems()`, which runs after the display's sync, so it also redraws on `gems_counted`. After a checkpoint restore the saved numbers are in place before the sync, so it shows them with no signal. The label turns green once every gem is collected, and a level with no gems (total 0) hides the row. Only the gems in group `"gem"` count, never the bonus gem. Replace the placeholder when there is HUD art.
- **Medkit** (`res://scenes/collectibles/medkit.gd` + `medkit.tscn`): `Area2D` with an `AnimatedSprite2D` (`sprites/collectibles/medkit.png`, 16×32 = 2 frames, `idle` at 2 fps) and a 12×12 sensor. Duck-typed like the gem: it calls `collect_medkit(heal_amount, points)` on any overlapping body that has it (the player); `heal_amount` (default 2) and `points` (default 10) are exported. The player heals up to `heal_amount` (clamped to `max_health`, nothing at full health), emits `health_changed`, awards the points and plays `collectibles/medkit`, and the medkit is taken on every touch — **points are awarded even at full health**, so being hurt first is never rewarded. It returns false (medkit left in place) only for a dead or dancing player. The overlap is polled every physics frame rather than using `body_entered`. A collected medkit frees itself; it joins `"saveable"` with empty state, like a gem, so it stays gone after a checkpoint restore. The health bar shows the gain as a reverse of the hurt flash (see Health bar).
- **Parallax backdrop** (`scenes/levels/backdrop_layers.tscn` + `backdrop_layer.gd`, `class_name BackdropLayer`; art in `sprites/backgrounds/`): purely visual, no physics. `backdrop_layers.tscn` is a `Node2D` holding a `Sky` (`CanvasLayer` at layer -100 with a full-rect `ColorRect`, the flat colour behind everything, unaffected by the camera) and two layers, `Far` (`z_index` -102, `scroll_scale` (0.15, 0.1)) and `Near` (`z_index` -101, `scroll_scale` (0.4, 0.3)), each a `Node2D` with the script and a centred `Sprite2D` child named `Art` whose texture is one tile (`bg_far.png`, `bg_near.png`: 320×180 placeholders, transparent above the silhouette, seamless sideways). Instance it once per level as the first child of the level root and edit through Editable Children (swap the `Art` textures, colours, scales). `scroll_scale` is per axis and means how fast the art moves on screen relative to a world object: 1 = like the world, 0 = pinned to the screen. A layer's position is the world point the camera must be looking at for its art to sit exactly as drawn in the editor; elsewhere it is displaced by `(camera centre - node position) × (1 - scroll_scale)`, so set the node's y to line the art up with the area being built (x is invisible while `repeat_x` is on). The position is a pure function of the camera — `get_canvas_transform()` read this frame, not a node reference or stored state — so respawn teleports and camera smoothing need no handling; `process_priority` 100 makes it run after the `Camera2D` updates, and `physics_interpolation_mode` is off because the node is moved from `_process()`. With `repeat_x` the script duplicates `Art` as many times as the visible width needs (`ceil(view width / tile width) + 2`) and wraps the row by whole tile widths; the tile must repeat seamlessly and there is no vertical repeat. Keep every layer's `z_index` far below the level's tilemaps (a basin draws at its tilemap's `z_index - 1`).
- **Finish** (`res://scenes/interactive/finish.gd` + `finish.tscn`, `@tool`): `Area2D` (layer 0, mask 1) with a sensor `CollisionShape2D` and a `PowerTarget` child (at the bottom-left tile; move it to the tile a wire should end at). Art `sprites/interactive/finish_locked.png` / `finish_unlocked.png` (two 32×32 frames, looping, red/green light) and `finish_open.png` (13 frames, plays once and holds); the `AnimatedSprite2D` and its `SpriteFrames` are built in code and never saved into the scene. Node origin is the bottom-centre of the art, on a 16px grid point (sits on the floor tile's top edge). **Unlock rule**: `required_gem_percent` (default 100) of the player's `gems_total` (`ceil(total × percent / 100)`; a level with no gems counts as met), and optionally a button through the `PowerTarget` (`sources`, or a conductor wire attached by adjacency; nothing wired = gems only), combined by `require_all` (true = gems AND button, false = gems OR button). The button is read through `set_powered()`/`set_powered_initial()` (the first call marks the finish as wired; `invert` is exported on the finish). It relocks if the rule stops holding (a released momentary button) until the player enters; the startup state is applied silently. **Entry**: the sensor is polled every physics frame (a player already standing in the doorway when it unlocks still enters); an unlocked finish plays `open`, plays `interactive/finish_open` and calls the player's `dance_through(center_x, slide_time, shrink_time)` (`slide_time` 0.4s, `shrink_time` 1.2s exported on the finish); once `open` has ended and that exit tween has finished it waits `complete_delay` (0.5s), emits `level_completed`, and adds `scenes/ui/level_complete.tscn` to the current scene. The player only shows in front of the open door if the Player node comes after the finish in the tree (or has a higher `z_index`). `interactive/finish_unlock` plays when it becomes unlocked after load. `next_level` (`@export_file`, a path rather than a `PackedScene`) is an optional override of where the overlay's Jump continues; empty = the next row after the current level in `LevelCatalog` (`Game.next_level_id()`), and none after the last (the prompt offers a replay).
- **Health bar** (`res://scenes/ui/health_bar.gd` + `.tscn`, `class_name HealthBar`, plus `health_segment_flash.gdshader`): `CanvasLayer` (layer 5) instanced as a child of `player.tscn`, so every level gets it with no level edits; it listens to the player's `health_changed` signal and syncs its starting state deferred (a child's `_ready()` runs before the parent's). Top-right via anchors; `pixel_scale` (default 3 in the script; `player.tscn` sets 2.5 to match the player camera's 2.5 zoom) and `margin` are exports. Art is `sprites/ui/healthbar1_{back,front,outline}.png` (128×16): `Back` has `clip_children = CLIP_AND_DRAW` so it is also the mask for its children (the bar keeps its rounded ends); `healthbar1_front.png` is cut in code into 4 full-bar-size `ImageTexture` `TextureRect` segments under `Back/Segments` (so each sits where it does in the art), cut per row along the art's curved ")" divider lines — `DIVIDER_X` 32/64/96 plus the per-row `DIVIDER_CUT` offsets, each segment keeping the divider line at its right end — not along straight verticals; the four pieces recombine to the original art exactly. Redrawn art with a different divider shape needs `DIVIDER_CUT` updated; `Outline` is on top. Segment i is full while i < health. Losing a hit point flashes that segment (3 blinks of 0.06s on / 0.06s off, `FLASH_STRENGTH` 0.6 toward white) via a per-segment `ShaderMaterial` that only lightens each pixel's colour (so the pixelated divider shading is kept), then hides it so Back's flat divider lines show; gaining health plays the reverse: the segment starts hidden and blinks in (normal, white, three times) before settling shown, with several gained at once filling in left to right `GAIN_STAGGER` (0.2s) apart; the first sync at load snaps without animating. This assumes `max_health` 4. The earlier slide-the-front-layer approach was dropped. The `healthbar1_text.png` ("HEALTH" label) layer is not used yet.
- **Level-complete overlay** (`res://scenes/ui/level_complete.gd` + `.tscn`): placeholder `CanvasLayer` (layer 10) built in code — dimmer, title, gem tally, prompt. `show_result(gems, total, next_id)` (a level id, empty = none); ignores input for 0.6s; `jump` calls `Game.load_level(next_id)` when there is one, otherwise the prompt is "Press R to play again" (`R` calls `Game.restart_level()` once the player has won, which discards the checkpoint). Replace the whole scene when real UI exists.
- **Pause menu** (`res://scenes/ui/pause_menu.gd` + `.tscn`, `class_name PauseMenu`, plus `res://scripts/level_catalog.gd`, `class_name LevelCatalog`): `Escape` (the `menu` input action) toggles a modal placeholder menu: a placeholder `CanvasLayer` (layer 20, above the level-complete overlay at 10) built in code — dimmer, title, a Resume button and one button per level, the current level's marked "(restart)". `Game` owns it (`open_menu()`, `close_menu()`, `toggle_menu()`, `is_menu_open()`): the menu scene instances under the viewport root, `Game` sets `get_tree().paused`, and both run in `PROCESS_MODE_ALWAYS`; the menu reads no Escape itself, `Game` handles it in both directions (so one press can't be handled twice) and `R` does nothing while it is open. Opening is ignored while a load is under way or with no level; it opens over the level-complete overlay too. **Pause freezes** physics, `_process`, tweens and every `Timer` (including the water manager and the player's death/respawn tween); the three `create_timer()` calls in game code (`Finish` completion delay, the overlay's accept delay, Drillbot's dwell) pass `process_always = false` so they stop as well, and **a new `create_timer()` must do the same**. **Audio while paused**: the `Audio` autoload is `PROCESS_MODE_ALWAYS`, so music keeps playing and one-shots already in flight finish; loops (`Audio.make_loop()`) are children of the nodes that own them and pause with them. Sounds `ui/menu_open`, `ui/menu_close` and `ui/menu_select` are in `Audio.PLANNED`. **Levels** are rows in `LevelCatalog.LEVELS` (`id`, `title`, `path`; list order is play order); `LevelCatalog.entries()` skips a row whose scene file doesn't exist, with a warning. The menu emits the row's id and `Game.load_level(id)` closes the menu (unpausing), discards the checkpoint (`restart_level()` semantics) and loads it, or restarts when the pick is the current level (marked by `Game.current_level_id`). Replace the whole scene when real UI exists.
- **Touch controls** (`res://scripts/touch_controls.gd`, `class_name TouchControls`, a `CanvasLayer` at layer 8: above the HUD (5), below the level-complete overlay (10) and the pause menu (20)): `Game` adds one as a child in `_ready()`, so every level has it with no level edits. It drives the existing input actions through `Input.parse_input_event(InputEventAction)` (so `Input.is_action_pressed()` polling and `_unhandled_input()` handlers both see it) and nothing else reads touch. Every touch is tracked by finger index, and after each event the held set of actions is recomputed from all fingers and only the differences are sent, so crouch + jump and crouch + kick (surf mount) work with two fingers, and a finger can slide from one button to another. Layout is placeholder art drawn in code, laid out against the visible rect and redone on `size_changed` (it grows past 1280×720 on wide screens): bottom left an 8-way D-pad (a touch within 1.5 radii grabs it and keeps it until release; left/right `move_left`/`move_right`, up `climb_up`, down `crouch`, diagonals press both axes for swimming; the vertical deadzone is larger than the horizontal so a drifting thumb can't crouch while running); bottom right JUMP and KICK; top centre pause (`menu`) and restart (`restart`, which fires only after `RESTART_HOLD` 0.6 s of holding, with a progress ring, because a respawn is costly). While `get_tree().paused` (the pause menu) it ignores new touches and releases everything; the menu's own buttons work through the engine's touch-to-mouse emulation. Visible when `DisplayServer.is_touchscreen_available()`, or from the first touch event if the platform doesn't report one; **F8 toggles it in a debug build and then the real mouse acts as one finger**, for checking the layout on a desktop (mouse events the engine emulates from touches are skipped, so a touch is never counted twice). Tuning is constants at the top of the script, not exports. The level-complete prompt says "Press R": on touch, hold the restart button (jump continues to the next level as before).
- **Checkpoint and save/restore** (`res://scripts/game.gd` autoload `Game`; `res://scenes/interactive/checkpoint.gd` + `checkpoint.tscn`): a checkpoint stores an in-memory snapshot of every saveable node; dying or pressing `R` reloads the level and re-applies it.
  - **Saveable contract**: a node joins group `"saveable"` in its own `_ready()` (never deferred — the restore runs before deferred work) and implements `save_state() -> Dictionary` (plain data only: bool/int/float/String/Vector2/Array/Dictionary, nothing referencing nodes or resources) and `load_state(d)`. `load_state` runs on the freshly loaded node after its `_ready()`, so it must snap (no animation, sound or edge event) and must not depend on any other saveable having been restored first. Snapshot keys are node paths relative to the scene root, so renaming or moving a saveable in a level just starts it fresh. A node that frees itself (gem, melted block, dead enemy) is absent from the snapshot, and `Game.apply()` frees the fresh copy of any saveable with no entry — such nodes only describe their alive state and need no "was I freed" flag. The snapshot belongs to the level id it was taken in and is discarded when another id is loaded (`has_checkpoint()` is false elsewhere, and `Game` ignores a moment with no level); nothing is written to disk.
  - **`Game` API**: `checkpoint_index` (-1 = none), `checkpoint_position`, `has_checkpoint()`, `commit_checkpoint(index, respawn_position) -> bool` (snapshots and stores the position only if `index` is strictly greater than the current one, then emits `checkpoint_committed(index)`), `clear_checkpoint()`, `capture()`, `apply(scene_override = null) -> bool`, `respawn()`, `restart_level()`; signals `snapshot_captured`, `snapshot_applied`, `checkpoint_committed`.
  - **Level loading** (`Game.load_level()`, `res://scripts/level_catalog.gd`): `Game` loads levels itself (not `change_scene_to_file()` or `reload_current_scene()`). `load_level(id, source = null)` closes the menu, ignores a call while a load is under way, treats a call for the id already loaded (no source) as `restart_level()`, otherwise clears the checkpoint and requests the swap. `_swap_level()` runs deferred, so it is safe from a signal or physics callback: it instantiates the source first (a failure leaves the old level alone), removes the old level from the tree at once and queues it for freeing (so two players never coexist and group lookups stay unambiguous), adds the new root under the viewport root and makes it `current_scene`. `Game` keeps `current_level_id`, the loaded root and the source it was built from; `restart_level()` and `respawn()` reload from that source. `level_root()` is the loaded root (null if none): `capture()`, `apply()`, the pause menu guard and `Finish`'s overlay use it, never `current_scene`. A level Godot started itself (the main scene, F6 in the editor) is **adopted** lazily by `_ensure_adopted()` (also queued from `_ready()`): its source is its own `scene_file_path` and its id the catalog row with that path, else a `path:` id from `LevelCatalog.id_for_path()`; a root with no file can't be reloaded. `LevelCatalog` is the built-in provider: `entries()`, `entry()`, `source_of(id)` (a row's path, or the path inside a `path:` id), `id_for_path()`, `next_after(id)`; `Game.next_level_id(override_path)` returns the `Finish` override's id if given, else `next_after(current_level_id)`. Live pitfall: the restore must still hang on the new root's `ready` signal and the checkpoint scope on `current_level_id`; both are set before `add_child()`, because checkpoints read `Game` in their own `_ready()`.
  - **Respawn flow**: `respawn()` (from `R` and the player's death timer) reloads the current level; if a checkpoint exists it also `apply()`s the snapshot and calls the player's `respawn_at(checkpoint_position)`, otherwise the reload is the level's initial state. The restore runs from the new level root's `ready` signal (connected in `Game._swap_level()` before the root enters the tree, so it needs no path matching): that fires after every node's `_ready()` — all saveables have joined their group — but before any deferred call queued by those `_ready()`s. Restored buttons therefore reach circuits and `PowerTarget`s before their first recompute, and wired devices snap through `set_powered_initial()` with no sound or animation; a wired device re-derives from its restored source rather than trusting its own saved frame. A second `respawn()` while a load is under way is ignored. After the player has won (`is_dancing`), `R` calls `restart_level()`, which clears the checkpoint first ("play again" starts from scratch). Music never restarts: `Audio.play_music` returns early when the requested track is already playing, and `Audio` is an autoload.
  - **What each type saves**: gem nothing; button `active`, `pressed` and, for a timed one, `time_left` (for 3 physics frames after restore an empty sensor doesn't clear `pressed`, so a block resting on a restored toggle button isn't read as a fresh press; `powered_changed` is emitted only if `active` changed); speed trap `powered`, `time_left`, the reading and whether it passed; arc receiver `powered` and `time_left`; zone sensor `powered` and `time_left` (for 3 physics frames after restore an empty zone doesn't clear `powered`, since a restored body only overlaps once the physics server has stepped; `powered_changed` is emitted only if `powered` changed); door `want_open` and exact frame (a door caught mid-travel resumes); `MeltableBlock` position, horizontal velocity and `melt_progress` (vertical velocity is dropped so a restored fall speed can't fire a false splash); laser turret `enabled`; arc turret `enabled`; mirror accumulated target rotation, last power level and (toggle mode) the aim index; moving platform phase within its loop and the running flag (the tween is rebuilt and fast-forwarded in 50ms slices, since a `Tween` can't be seeked); crusher clock, segment, powered, parked and jammed flags; see-saw `angle`, `angular_velocity` and `motor_dir`; drillbot position, facing and health (a bot saved mid-dwell resumes walking and restarts the dwell at its patrol end); stingbot position, health, phase, all five timers and facing; basin `liquid_type` (an empty basin is claimed by whichever liquid arrives first, so it can differ from the authored export), `fill_volume`, `has_crust`, `crust_top_row`, `crust_bottom_row` (crust set first, since the fill limit depends on it; collision rebuilt, ripple cleared); camera cue `fired` only (what its `once` needs; the cue itself is never saved and a restore never plays one, and `load_state()` clears a pending delay and a pending pass-through, which the first apply re-derives); logic nodes `powered`, the last input level and their own state (delay: pending target and seconds left; latch: reset level; counter: count, each source's last level, reset level, auto-reset time left; pulse: seconds left), snapped silently with `powered_changed` only on a change and the inputs re-read once, deferred, without an edge; player `gems_collected`, `gems_total` and `points` only (position and health come from `respawn_at()`).
  - **Not saved**: in-flight liquid particles, bullets, arcs and explosions (cleared by the reload, so a basin mid-overflow comes back settled); the drop platform (always returns armed at its original spot); faucets, conveyors, cannons, sawwheels, jump pads and the finish, which re-derive from restored power and gem state; checkpoints themselves.
  - **Checkpoint** (`checkpoint.gd`, `Area2D`, layer 0, mask 1): `sprites/interactive/checkpoint.png`, 16×112 = 7 frames on one `Sprite2D` (`vframes` 7), frame 0 inactive, 6 lit, a light climbing the pole between; node origin is the centre of its 16×16 tile. `order` (exported) is assigned automatically when an instance is added to a scene in the editor — the lowest whole number from 1 up that no other checkpoint in the edited scene uses, so sequential adds get 1, 2, 3 and a number freed by deleting a checkpoint is reused by the next one added; it stays hand-editable, instances already saved in a level are never renumbered, and a duplicate or paste is numbered like any new node (the script is `@tool` only for this: in the editor `_ready()` numbers a node whose `owner` is still null, meaning it was just added, and returns before touching the `Game`/`Audio` autoloads, which don't exist there; the root of `checkpoint.tscn` itself is skipped). A touch counts only if it is greater than `Game.checkpoint_index`, so a later checkpoint overrides an earlier one and never the reverse; two checkpoints in one level sharing an `order` get a warning, and would light together (the second can never override the first). The sensor is polled every physics frame, so a player already inside at load still counts; a dead or dancing player never activates one. Activating calls `Game.commit_checkpoint(order, global_position + respawn_offset)` (`respawn_offset` default `(0, -1)`: the player's capsule is 16px tall and centred, so the tile origin puts its feet on the tile's bottom edge) and plays `interactive/checkpoint` (listed in `Audio.PLANNED` until a file exists). A checkpoint is lit while its `order` is at or below `Game.checkpoint_index`: on `checkpoint_committed` every checkpoint in that range animates 0→6 at `anim_fps` (12) if it isn't already lit, so earlier ones stay lit and skipped ones light up with it (only the touched one plays the sound); a level that loads onto a restored snapshot starts with all of them already lit, silently. Place it before the Player in the level tree so the player draws in front.
  - **Live pitfalls**: a new saveable must join the group in `_ready()` (not deferred) and its `load_state` must be silent and order-independent; anything that recounts or caches level totals at load (like `gems_total`) must survive the restore having already freed collected objects; `load_state` on anything a power source drives must tolerate `set_powered_initial()` running afterwards and winning.

Reads with: `player.md` (`respawn_at()`, death, gems and win), `power.md` (the finish, restored power state), `enemies.md` (enemy restore rules), `rotating-bodies.md` (restoring a rotating body), `platforms-conveyors.md` (the drop platform is not saved), `liquid-system.md` (a basin comes back settled).
