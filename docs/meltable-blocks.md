# Meltable blocks (ice, metal and carbon fiber)

The `MeltableBlock` base class, its three subclasses, `IceBlock`, `MetalBlock` and `CarbonFiberBlock`, and the `BlockDispenser` that makes them. Read `objon.md` (the core: setup, layers and groups, contracts, invariants, docs index) first.

Covers: Meltable block; Ice block; Metal block; Carbon fiber block; Block dispenser

- **Meltable block** (`res://scripts/meltable_block.gd`, `class_name MeltableBlock`): base class of `IceBlock`, `MetalBlock` and `CarbonFiberBlock`; a subclass supplies only what differs — `_apply_forces()` (gravity/buoyancy/drag into `velocity`), `_touching_slag()`, `_melt_liquid_type()`, `_melt_sound()`, `_shunt_sound()`, `_walk_push_sound()`, `_break_apart()` (carbon fiber), `_draw_block()` (and `is_slippery()` on ice). Don't override `_ready()`/`_physics_process()` without calling `super()`. Inspector values that differ per subclass live in the subclass's `.tscn` (metal_block.tscn overrides `melt_time`, `slag_melt_time`, `cool_rate`, `shunt_speed`, `float_depth_fraction`, `absorbs_bullets`; ice_block.tscn sets `brittle`; carbon_fiber_block.tscn sets `mass`, `brittle`, `walk_push_speed`, `float_depth_fraction`), not in `_init()`, because Godot skips saving a value equal to the base script's default. `@tool` `RigidBody2D` on layers 1|2, mask 1|2, sized in 16px tiles via `size_tiles` (its collider is an octagon, corners bevelled by `chamfer_px`, default 1, so it doesn't snag on tile seams; each scene holds a `ConvexPolygonShape2D` that is `resource_local_to_scene`, so resizing one instance never touches another), falling under gravity until it lands. Rotation is free by default; an instance sets `allow_rotation` false to lock it upright (see Rotation below). Gravity, buoyancy and drag are integrated by hand (`gravity_scale` 0, engine damping replaced with 0, no sleeping, a friction-0 physics material, contact reporting on — all set in `_configure_body()`), so the constants keep their meaning and the engine only solves contacts; `velocity` is a scratch copy valid inside `_physics_process()` and the subclass hooks, and the real velocity is `linear_velocity`. Horizontal motion is **own motion** (`_own_vx`: kick, its decay, liquid drag, underside push) plus **carry** (conveyor speed, and with `carry_assist` the velocity of the world body under it, see Moving floors below), written to `linear_velocity` each frame; `_integrate_forces()` runs first each tick, scans the previous step's contacts (floor, wall, actor side, belt, floor velocity — read orientation-independently) and accepts the solver's change to the written velocity into own motion. **Static friction** is `_is_held()` (the engine contact has friction 0): an idle block on a floor no steeper than `hold_slope_degrees` has gravity cancelled, so it neither creeps nor sinks; on a steeper floor gravity acts and it slides (ice 8° in `ice_block.tscn`, metal and the base default 30°). A rotating block is held only while its floor contacts sit under its centre of mass (give or take `SUPPORT_TOLERANCE`) and while it leans no more than `HOLD_TILT_MARGIN` beyond the surface under it, so one overhanging a ledge still topples. **Moving floors:** carry is the floor's velocity at the block's *centre* in both axes (the contact's velocity plus `ω × lever`, with ω from the floor body's `get_angular_velocity()` when it has one — `RotatingBody` and rigid blocks do, tiles report 0), and a held block takes the floor's vertical velocity instead of zero, so a tilting or lifting platform never presses into it (a frictionless, tilted push would otherwise leak into own motion and creep it off); `carry_assist = false` turns both off. On a body floor (a plank, another block) a held rotation-allowed block also takes the floor's angular velocity, discarding the solver's angular change, and its righting spring targets the floor's tilt (`_floor_tilt`, from the flattest floor contact; 0 for tiles) instead of world-upright, so it turns with a plank, including through a swing reversal. The contact report can drop one corner of a flat contact on a moving body for a frame or two, so the support test is latched for `SUPPORT_LATCH_FRAMES` (12) on body floors only; tile floors keep the strict test and a block still topples off a tile ledge at once. `debug_hold` prints floor/hold state about six times a second while the block rests on a floor. Each instance copies its collision shape in `_ready()` as a backstop. **Weight:** the engine's `mass` is the block's weight, set per 16px tile in the scene (metal 4, ice 1, carbon fiber 0.5) and multiplied by the block's area in `_configure_body()`; it sets how contacts trade momentum between blocks and is what a rotating body reads as a block's load, and has no part in gravity or buoyancy (hand-integrated per unit mass). Joins `"water_solid"` and `"ground"` while intact. Implements `on_laser_hit()` by stamping `Engine.get_physics_frames()`; its own physics step treats a hit within the last 2 frames as lit, so it is independent of turret processing order. Heat: lit, `melt_progress` rises over `melt_time`; touching slag, over `slag_melt_time`; the faster wins; with neither it drains at `cool_rate`. At 1.0 it disables collision (deferred), leaves both groups, plays the subclass's melt sound, calls `WaterManager.spawn_melt_particles(cell, liquid_type, world_center, rotation)` once per 16px cell it covers, passing each cell's exact world position and the block's rotation so the burst is spread over the cell in the block's own frame (a snapped, axis-aligned spread started particles inside the plank under a block resting on a see-saw, where they fell through), and frees itself (the manager tolerates a freed registered solid). **Art tiling** (`_draw_art(texture, tile_origin, rect)`, with `mirror_tiling` exported, default on): a block bigger than one 16px tile along an axis doesn't repeat the tile per cell. The first and last 75% of the tile (source 0–12px at the start, 4–16px at the end) appear only at the block's two ends, and the span between is filled with the tile's middle band (source 4–12px, `MIRROR_EDGE_FRACTION` 0.25) ping-ponged, every copy mirrored against its neighbours, so a 2-tile axis is 0–0.75 normal, 0.75–1.25 the mirrored band, 1.25–2 normal. Each axis is independent, boundaries are whole pixels, and mirrored pieces are drawn through a flipped `draw_set_transform_matrix()` (reset afterwards). A 1-tile axis, or `mirror_tiling` off, draws the plain tile. Subclass sprites go through this helper. Kickable: `kicked(direction)` (the optional kick contract in player.gd, alongside `take_damage()`) sets its own horizontal motion to `shunt_speed` away from the kicker, decaying at `slide_friction` while on the floor; it can slide off ledges and stops against walls and other bodies; `shunt_speed <= 0` makes a block unkickable. **Surf shove** (`surf_shoved(direction, surf_speed) -> float`, the optional contract the player's bowl sweep reads): the block's own motion becomes `surf_speed * surf_shove_transfer / sqrt(mass)` (default transfer 0.5, so a heavy block takes less), never below `shunt_speed` and capped at `surf_shove_max_speed` (200; on ice that slides about 18 tiles at `slide_friction` 70), and a block already sliding that way is never slowed; the cost to the surfer is `given * mass / (mass + 2)` (2 mirrors the see-saw's `player_weight`). It returns -1 and refuses when `shunt_speed <= 0`, when melted, or when `_hit_wall` is set on the side the surfer pushes from (`_wall_side` from the last contact scan: a tile wall or another body pressed against that face), so such a block stops the surf like a wall; a block 1 px short of a wall is still shoved and the surfer then passes through it into the wall. Plays the block's shunt sound. Inspector: group "Surf". **Jump pad launch** (`launch(vector)`, the duck-typed contract `jump_pad.gd` calls on anything that has it, as on the player): the vector is divided by `mass ^ launch_weight_exponent` (default 1; mass is per tile times area, so a 1x1 ice block takes it whole, a 1x1 metal block a quarter of the speed, about half a tile of height from a 500 px/s pad, and a bigger block lifts less) and buffered in `_launch_vector`; `_physics_process()` applies it once, after the hook, floor friction and the held-block vertical zero have edited `velocity` and just before the write to `linear_velocity`, replacing the block's velocity outright (own motion and vertical), so nothing in the tick can cancel it and the pad's Area2D signal can fire at any point in the step. The pad triggers on `body_entered`, so a block is launched once per entry (a block that lands back on the pad is launched again); a melted block ignores it, an unkickable one is launched all the same, a hanging player is released by the block's speed (`hang_max_speed`), and the buffer isn't saved. The hand-integrated gravity clamps vertical speed to ±`MAX_FALL_SPEED` (400) on the tick after, so a straight-up launch is capped at 400 px/s whatever the pad's `launch_speed`. Inspector: group "Launch". **Material flags** (exports, so a scene sets them and no subclass overrides code for them): `brittle` (ice and carbon fiber true, metal false) and `absorbs_bullets` (metal true). **Shatter** (`shatter()`, the contract `crusher.gd` calls): if `_shatters_when_crushed()` (the `brittle` flag) is true it runs `_break_apart()` at once: the base class's is `_melt()`, the block's own melt path rather than a separate delete, so it plays its melt sound, spawns the same per-tile water burst as a full melt, and frees itself (ice); carbon fiber overrides it with a quiet `dissolve()`. A block that doesn't shatter, or has already melted, ignores it. **Bullets** (`on_bullet_hit(point, direction) -> bool`, the optional contract `bullet.gd` calls on any body it overlaps): a block with `absorbs_bullets` consumes the bullet with `interactive/metal_ping` and is unharmed; a `brittle` block consumes it and breaks as under a crusher; any other block, or a melted one, returns false and the bullet flies on. A bullet never ignores a block of ice, metal or carbon fiber. **Walk push** (`walk_shoved(direction, walk_speed) -> float`, the optional contract the player calls while it walks into the block's side, see Walk push in `player.md`): `walk_push_speed` is the cap on the speed it can be pushed at and 0 (the default: ice and metal) refuses with -1, so the shove guard below still holds for them. A block with a speed asks a thin shape query just past its leading face (`_bodies_in_front()`, 4 px deep, layers 1|2, not the contact scan: a block resting flush against another reports no contact) what is in front: anything but another `MeltableBlock` (a tile, an enemy, a body) refuses, and each block ahead is asked in turn (`_walk_push_limit()`, up to 8 deep), so the speed is the slowest cap in the chain with `chain_push_slowdown` (0.75) applied per extra block; any block ahead that refuses (ice, metal, a wall behind it) refuses the whole push. It returns the lesser of that limit and the walk speed, gives every block in the chain that speed as own motion (`_walk_push_apply()`) and plays `_walk_push_sound()` when a push starts. Floor friction is skipped while a push is live. The push ends `WALK_PUSH_GRACE_FRAMES` (2) after the last call (`_end_walk_push()`): on a floor that is not slippery (`_floor_slippery`, the floor answering `is_slippery()`, from the contact scan: a frozen crust or an ice block) the block stops at once; on a slippery floor, in the air or in liquid its own motion carries on and decays as for a kick. A kick or surf shove ends the flag. The shove guard (`reject_actor_shove`) stays on for every block, carbon fiber included: the push is the block's own motion, so the guard only discards the solver's extra, and an enemy or any other actor still cannot move it. **Dissolve** (`dissolve()`, called by a `BlockDispenser` on its oldest block): the quiet way out. It does what a melt does to the world (`_leave_world()`: `is_intact()` turns false, physics stops, the block leaves `"water_solid"` and `"ground"`, a hanging player is released, collision is disabled) but spawns no liquid and plays no melt sound; the block is frozen in place, fades its alpha to 0 over `DISSOLVE_TIME` (0.2s) and frees itself. A block already melting or dissolving ignores it. **`spawner_owned`** (plain variable, set before `add_child()`): the block then does not join `"saveable"`, because its dispenser saves and re-creates it (see Block dispenser). Buoyancy helpers: `_submerged_fraction(liquid_type)` (the area of the block's rotated rectangle below the settled liquid surface of the basin at its centre column, a polygon clip, via `WaterManager.get_basin_for_column()` and `get_liquid_surface_world_y()` so crust doesn't count; it also records the submerged area's centroid, the centre of buoyancy) and `_buoyant_accel(submerged, riders, liquid_type)`, `GRAVITY * (1 - submerged / rest_fraction)` (plus, with rotation allowed, the couple between the centre of buoyancy and the centre of mass as angular acceleration) where `rest_fraction = float_depth_fraction + riders * rider_load_tiles / block area` — zero net force at the rest fraction, upward when deeper, and `rest_fraction >= 1.0` can't carry the load and sinks (the carrying-capacity lever for level design). Riders: `_actors_in_band()` (a thin `intersect_shape` band across the top face of the block taken as an upright rectangle, width and height swapped on its side, counting layer-1-only bodies, never a player hanging from this block) is applied the instant a rider is detected, so behaviour doesn't depend on the block having settled. **Rising and draining levels:** a floating block rides the surface. `_damp_vertical_in_liquid(coefficient, submerged, riders, liquid_type, delta)` (used by ice and by metal on slag) damps `velocity.y` relative to the liquid's own vertical speed, `WaterBasin.get_liquid_surface_velocity_y()` scaled by `submerged / rest_fraction` (clamped 0..1), so a block at its rest fraction follows a rising or draining level instead of lagging it, and the surface can't overtake a rider's swim probe. A rider can't hold the block back: in `_integrate_forces()`, while an actor touches the top face (`_rider_on_top`), no roof is hit and every rider has room above (`_riders_free_above`, a `test_move()` per rider in the physics step), a solver-reduced rise (`vel.y > _written_vy` with `_written_vy < 0`) is reset to the written velocity, and the rider is pushed up by its own depenetration. Under a ceiling the contact stops the block as before. The player completes it from its side by leading a rigid floor (see Rising rigid floors under Player). Dropping layer 1 from the block's mask does not work on a rigid body (a pair interacts if either side's mask matches), and a collision exception against the rider makes it fall through (below). **Don't use a collision exception against the rider** — Godot applies exceptions to both bodies, so the rider would fall through. Ledge-hangable via group `"ground"` (`hang_platform` is typed `PhysicsBody2D`, not `AnimatableBody2D`, for this reason; the hang follows the block's whole transform as it bobs, slides or tilts, `_follow_hang_platform()` mapping every pinned point through the platform's change of transform; `is_hangable()` is the block's say: a locked block always, a rotation-allowed one only within `hang_max_tilt_degrees` (10) of resting flat, at most `hang_max_speed` (90 px/s) and `hang_max_spin` (1.2 rad/s), refusing the grab otherwise and force-releasing a held hang (`_force_release_hang()` in `player.gd`, which also stops a mantle in progress); a melt releases a hanging player by clearing `is_hanging`, as `drop_platform.gd` does). While a player's hang is attached to the block (grab through the end of the mantle), the block and player hold a mutual collision exception (`_update_hanger_exception()`), dropped the frame the hang ends: the mantle tween carries the player's collider through the block's top corner, and without the exception the contact between them pushes the block while `_follow_hang_platform()` drags the mantle target with it, so the push can feed itself. **Any other actor-driven teleport onto a `CharacterBody2D` platform needs the same treatment.** Carried by conveyors: `_scan_contacts()` reads `get_conveyor_speed()` off the floor it rests on (ice and metal alike, regardless of slipperiness or weight) as carry, added to the written velocity but never to own motion; a block carried into a wall stops there, with no stored push-back left to creep it away. **Rotation** (`allow_rotation`, default true; false = locked upright): hand-integrated in `_integrate_forces()` like the rest. The solver's angular change (a corner landing, a ledge overhang) is accepted, then a soft spring pulls toward the nearest 90° (`righting_stiffness`) and angular drag (`angular_drag`, plus `angular_drag_liquid` scaled by the submerged fraction) damps it, so a block topples when its support goes but settles flat, upright or on its side. The centre of mass is lowered by `com_drop` (a fraction of half the height). The buoyancy couple lifts a tilted floating block's low side. Riders apply their weight straight down at their feet: a torque `lever_x * weight / gyration²` about the centre of mass (`_rider_torque()`, with `rider_load_tiles` setting how hard), cancelled while the block and its riders together balance over the floor contacts (`RIDER_SUPPORT_TOLERANCE`), so a rider near the edge of a supported block doesn't rock it or the blocks stacked on it, while a rider on the overhang of a perched block still tips it. Actor side contacts are classified in the block's upright frame and the shove guard's angular half only discards spin that increases angular speed beyond what was written. `save_state()` adds `angle` and `angular_velocity` unless the block is locked. Kicks act at the centre of mass (linear velocity only), so a block slides rather than topples. Actors can never shove it by contact: kinematic bodies hand a rigid body velocity through the contact solver, so the shove guard in `_integrate_forces()` (`reject_actor_shove`) removes any horizontal speed an actor's side contact gave it away from that actor, and the displacement it caused; walking into a block, or a block sliding into an actor, just stops it, so it only moves under its own motion (a kick, its own friction, buoyancy, the surf shove, and for carbon fiber alone the walk push above). A block it hits is pushed by the contact in proportion to `mass`.
- **Ice block** (`ice_block.gd`, extends `MeltableBlock`): melts to `WATER` (`melt_time` 2s, `cool_rate` 0.5 — it refreezes); `shunt_speed` 100 px/s, `slide_friction` 70 px/s². Molten slag melts it much faster: while any part of it is below a `SLAG` basin's liquid surface (`_touching_slag()` → `_touching_liquid()`: the four rotated corners and the bottom midpoint, each against its own column's basin; crust doesn't count) progress rises over `slag_melt_time`, so the burst of water lands on the slag and crusts it. Slippery: `is_slippery()` returns true (player floor contract, above), so standing on any ice block gives ice-rink acceleration and friction. `get_surf_friction_scale()` returns `surf_friction_scale` (0.25), so a surfboard coasts about four times as far on it (see Surface friction under Surf). Brittle (`brittle` true in `ice_block.tscn`): a cannon bullet or a crusher's spike breaks it through the melt path, so it bursts into water. Plays `interactive/ice_shunt` on a kick, `interactive/ice_melt` on melting, `interactive/ice_splash` on first touching water at speed. Buoyant in settled `WATER` only (`float_depth_fraction` 0.8: floats at ~80% submerged, rises back with a small bob if pushed under, lifts off the seabed; slag does not float it), with drag scaled by the submerged fraction — `water_drag` vertically (heavy, so the bob settles; relative to the surface's own vertical speed, see Rising and draining levels in the Meltable block bullet) and the much lighter `water_drag_horizontal` sideways (so a shunt or an underside push keeps drifting until it hits something). The liquid surface used for buoyancy is the basin at the block's centre column, so a wide block half over a wall floats as if over its centre. An actor pressing on the underside of a block that is in water nudges it sideways: `_apply_underside_push()` accelerates the block toward `underside_push_factor` (0.25 by default, 0 = immovable) times the actor's horizontal speed, at a fixed rate, never braking it (water drag stops it), detected with the same kind of band query as riders. This is the only contact-driven horizontal influence an actor has — the block never rides an actor and the shove guard discards sideways contact pushes, so removing this function makes floating blocks immovable by swimming. Art is `sprites/interactive/ice.png`, 16×112 = 7 frames of 16×16 (frame 0 solid, 1–6 the melt), drawn in `_draw_block()` through `MeltableBlock._draw_art()` (see the Meltable block bullet: mirrored tiling for blocks bigger than one tile); `melt_progress` selects the frame (`int(melt_progress * 7)`), so a block that cools and refreezes plays the animation backwards.
- **Metal block** (`metal_block.gd`, extends `MeltableBlock`): the heavy counterpart to the ice block; melts to `SLAG` (`melt_time` 3s, `cool_rate` 0.4), plays `interactive/metal_melt`. Not slippery. Kickable like ice but sluggish: `shunt_speed` 50 px/s in `metal_block.tscn` (a kick moves it about one tile; `slide_friction` is the shared 70), plays `interactive/metal_shunt`. Also heated by slag: it floats on a `SLAG` basin (`float_depth_fraction` 0.6 in the scene, `rider_load_tiles`, `slag_drag`; only the still-liquid surface counts) but while any of it is below the slag surface at its centre column `melt_progress` rises over `slag_melt_time` (8s), so a slag raft has a limited life. In water it doesn't float: plain gravity slowed by `water_drag`, so it sinks to the seabed. The liquid drag coefficients damp sideways motion too, so a kicked block in liquid stops quickly. Slag onto a water basin crusts it, slag onto a slag basin rejoins it. It jams a crusher: `jams_crusher()` is true while it hasn't melted (see Sawwheel / Crusher hazards). It absorbs bullets (`absorbs_bullets` true in the scene): a cannon bullet is consumed with a ping and the block is unharmed, so a metal block is a bullet shield. Drawn in code (grey steel glowing orange as it heats) until sprites exist. When its sprite exists, `_draw_block()` should draw it through `_draw_art()` like the ice block so larger blocks get the same mirrored tiling.

- **Carbon fiber block** (`carbon_fiber_block.gd` + `carbon_fiber_block.tscn`, `class_name CarbonFiberBlock`, extends `MeltableBlock`): the light block that lasts. Placed, sized, kicked, hung from and dispensed like the others (layers 1|2, `water_solid`, `ground`, saveable, `block_scene` of a dispenser). **Never melts**: `on_laser_hit()` does nothing (a beam only stops on it), `_update_melt()` is empty and `_touching_slag()` is false, so `melt_progress` stays 0 and a carbon fiber block is a permanent laser shield and a permanent slag raft; a level that wants a disposable shield or a timed raft offers no carbon fiber block. **Light**: `mass` 0.5 per tile (ice 1, metal 4), so a lone 1×1 cannot press a weight plate whose threshold is 2 (stacked blocks or a rider still can) and a see-saw reads it as a small load; a jump pad's vector is divided by `max(mass, 1)^launch_weight_exponent`, so a 1×1 is launched like a 1×1 ice block and a bigger one lifts less. **Liquids**: buoyant in both water and slag at `float_depth_fraction` 0.6 (plus rider load, as for the others), each with the drag of the liquid it is in (`liquid_drag` 6 vertical, `liquid_drag_horizontal` 1.2 sideways, scaled by the submerged fraction, vertical relative to the liquid's own motion so it rides a rising level); no splash sound and no underside push. It jams nothing (`jams_crusher()` false). **Brittle**: a bullet or a crusher's spike calls `_break_apart()`, which plays `interactive/carbon_break` and `dissolve()`s it (a quiet fade, no liquid, no steam). **Walk-pushable**: `walk_push_speed` 75 (half of walk speed) and the base class's chain rules (see Walk push in the Meltable block bullet), the one block a walking player can move; `slide_friction` is the shared 70, so after a push on a slippery floor it coasts about as far as a kick. Kick: the base default `shunt_speed` 100, sound `interactive/carbon_shunt` (also the walk-push sound). Placeholder art drawn in code (a dark woven tile) until sprites exist; when a sprite exists `_draw_block()` should draw it through `_draw_art()`. Sounds `interactive/carbon_shunt`, `interactive/carbon_break` and (from the base class) `interactive/metal_ping` are in `Audio.PLANNED`.

- **Block dispenser** (`res://scenes/interactive/block_dispenser.gd` + `block_dispenser.tscn`, `class_name BlockDispenser`, `@tool`): a powered device that makes blocks, so ice and metal are a renewable resource. A plain `Node2D` with a `SpawnPoint` `Marker2D` (default one tile below the node; the block's centre goes there) and a `PowerTarget` child; placeholder art is drawn in code (a steel housing with a light, green = ready, amber = cooling down, and an editor-only outline of the spawn area behind `show_spawn_area`). Exports: `block_scene` (a `PackedScene` whose root is a `MeltableBlock`: `ice_block.tscn` by default, or `metal_block.tscn` or `carbon_fiber_block.tscn`), `size_tiles` (applied to each spawned block), `max_alive` (default 1, 0 = unlimited), `cooldown` (default 0.5s, 0 = none), `invert`, `show_spawn_area`. **Power:** a rising edge of the final power state spawns one block; a falling edge does nothing. The startup state is not an edge (`set_powered_initial()` does nothing), so a level never loads with a block waiting, and an unwired dispenser never spawns. **Cooldown:** an edge during the cooldown is dropped silently; the cooldown starts only after a block was actually spawned. **Spawning** runs deferred (a source can change inside a physics callback, where adding a body is not allowed): the block is created upright and at rest as a sibling of the dispenser (so the dispenser's own transform never moves it), fades in over `FADE_IN_TIME` (0.2s) and is solid from its first frame; `interactive/dispenser_spawn` plays at the spawn point. **Occupied spawn area:** before anything else happens, an `intersect_shape` over the block's footprint (inset 0.5px per side, layers 1|2, so the player, enemies, blocks and tiles all count; the same query the door makes before closing) must come back empty. If not, the edge is dropped, `interactive/dispenser_blocked` plays, nothing is retired and no cooldown starts. **`max_alive`:** the dispenser keeps its blocks oldest-first and counts only intact ones, so a melted or shattered block frees its slot. When a new block would exceed the limit, the oldest are retired through `dissolve()` (a quiet fade, no liquid; `interactive/dispenser_dissolve` plays at a lowered volume), and those blocks are left out of the occupancy query, since the block sitting on the spawn point is what is being replaced; the old block is only dissolved if the new one can be made. **Checkpoints:** a spawned block is `spawner_owned`, so it is not saveable; the dispenser is. `Game.apply()` frees every saveable with no snapshot entry and snapshot keys are node paths, so a runtime block could never survive a restore on its own. Each block gets the explicit name `<dispenser name>_block_<serial>` (the serial is saved and never reused). `save_state()` returns each live block's name and its own `save_state()` (so exactly what `MeltableBlock` saves), the serial and the cooldown left; a dissolving block is not saved. `load_state()` frees any block the fresh copy already has, re-creates the saved ones (no sound, no fade, no edge, independent of restore order) and calls each one's `load_state()`; a restore never spawns. A level that is restored therefore has the blocks that were alive at the checkpoint and none made since. Level design: the spawn area must be free of anything solid when the edge arrives, the dispenser dissolves its own oldest block but never another dispenser's, and a block it spawned is an ordinary block (kickable, meltable, a plate weight, a hang) until it goes. The dispenser is a general mechanism for runtime-created saveables: the owner names them, they stay out of `"saveable"`, and the owner saves and re-creates them.

Reads with: `liquid-system.md` (melting, buoyancy, crust, slag), `rotating-bodies.md` (block weight and loads on a plank), `hazards-traps.md` (crusher jam and shatter), `lasers-arcs-mirrors.md` (`on_laser_hit()`), `player.md` (kick, rising rigid floors, slippery floors), `player-surf.md` (`surf_shoved()`, the ice friction scale), `platforms-conveyors.md` (conveyors carry blocks), `power.md` (the dispenser is a powered device), `saving-levels-ui.md` (the saveable contract the dispenser satisfies for its blocks).
